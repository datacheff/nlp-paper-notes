# IterCQR 쉽게 읽기: 대화 속 질문을 검색어로 바꾸기

[논문 노트](README.md) · [상세 설명](detailed-explanation.md) · [사전·사후 퀴즈](quiz.md) · [핵심 참고문헌](references.md) · [공식 원문](https://aclanthology.org/2024.naacl-long.449.pdf)

다른 AI 분야의 학습·최적화 경험이 있다면, **LLM으로 만든 초기 pseudo-label → 후보 생성 → 검색 관련 보상으로 학습**이라는 연결부터 잡으면 된다. 이 문서는 이해를 돕는 해설이며, 저자의 주장·실험 근거는 연결한 원문에서 확인한다.

## 1. 무엇을 만드는 모델인가?

IterCQR는 대화형 검색 앞단의 **질문 재작성기**다. 대화의 생략·대명사를 풀고 필요한 맥락을 더해, 기존 검색기에 넣을 독립적인 질의를 만든다. 최종 사용자 답변을 직접 생성하거나 검색기를 새로 학습하는 방법과는 역할이 다르다. [원문 §3.1](https://aclanthology.org/2024.naacl-long.449.pdf#page=3), [Fig. 1](https://aclanthology.org/2024.naacl-long.449.pdf#page=1)

다음은 **직접 만든 가상 예시**다. 논문의 데이터나 모델 출력이 아니며, 가상 박물관의 사실을 검증한 것도 아니다.

```text
이전 질문: 별빛박물관은 어떤 곳이야?
이전 답변: 우주 관측의 역사를 소개하는 박물관이야.
현재 질문: 거기 월요일에도 열어?

재작성 예시: 별빛박물관의 월요일 운영 여부는?
검색 결과 예시: [운영 안내 문단, 방문 안내 문단, ...]
```

`거기`만 검색하면 장소가 빠진다. 재작성은 이 누락을 채운다. 마지막 줄은 검색된 **문단 목록**이고, “월요일에 연다”라는 답변은 아니다. 답변 생성기를 붙일 수는 있지만 그 품질까지 이 논문의 검색 점수가 보장하지 않는다.

## 2. Rewrite와 retrieval을 분리해서 보기

```text
현재 질문 + 이전 질문·답변
          ↓ T5-base 재작성기
     독립적인 검색 질의
          ↓ 기존 검색기
       순위가 있는 문단들
```

여기서 T5는 텍스트를 입력받아 텍스트를 출력하는 모델이다. 검색기는 질의로 문서 집합을 뒤진다. 논문은 **BM25**와 **ANCE**를 평가한다. BM25는 단어의 일치와 빈도·문서 길이 등을 활용하는 sparse 검색 방식이다. ANCE는 질의·문단을 dense 벡터로 표현해 관련성을 점수화한다. “문장을 자연스럽게 고치기”와 “정답 문단을 높은 순위에 올리기”는 서로 다른 목표다. [원문 §3.3, Table 1](https://aclanthology.org/2024.naacl-long.449.pdf#page=5)

## 3. 첫 재작성기는 어떻게 준비하나?

먼저 `gpt-3.5-turbo`로 학습 대화의 초기 rewrite를 만든다. 이를 정답 텍스트처럼 사용해 T5-base를 NLL로 학습한 것이 초기 모델 `M₀`다. NLL은 여기서 “이 입력에서 초기 rewrite를 출력할 확률을 높이는 학습”으로 이해하면 된다. 초기 LLM 출력이 검색에 최적이라는 가정은 하지 않는다. 그다음 반복에서 검색 신호로 보완한다. [원문 §3.2.1](https://aclanthology.org/2024.naacl-long.449.pdf#page=4), [§4 Implementation Details](https://aclanthology.org/2024.naacl-long.449.pdf#page=6)

**사람 rewrite 불필요 ≠ 주석 데이터 불필요.** 사람이 대화 질문을 독립 질문으로 고쳐 놓은 label은 쓰지 않지만, 보상을 계산하려면 학습 질문에 대응하는 **gold passage**, 즉 정답 근거 문단을 알아야 한다. 따라서 완전한 무주석 학습이라고 부르면 잘못이다. [원문 §2.1, §3.2.2](https://aclanthology.org/2024.naacl-long.449.pdf#page=3)

## 4. 후보를 어떻게 평가하나?

이전 반복의 T5 모델이 beam search로 입력마다 **10개 후보**를 생성한다. 고정된 ANCE 인코더로 후보와 gold passage를 벡터화하고, 둘의 **코사인 유사도**를 보상으로 쓴다. 인코더를 고정하므로 이 과정에서 ANCE가 함께 업데이트되는 것은 아니다. 원문은 보상에 min-max 정규화를 적용해 `[0,1]`로 맞춘다고 설명한다. 세부 정규화 범위와 예외 처리는 본문만으로 확정하지 말고 코드에서 확인해야 한다. [원문 §3.2.2, Eq. (3)](https://aclanthology.org/2024.naacl-long.449.pdf#page=4), [§4 구현 조건](https://aclanthology.org/2024.naacl-long.449.pdf#page=6)

직관적으로는 “이미 아는 정답 문단의 의미에 어느 후보가 더 가까운가?”를 묻는다. 이는 후보마다 전체 문서 집합에서 검색해 MRR을 직접 계산하는 것과 다르다. 정답 벡터와 가까워져도 경쟁 문단이 더 가까우면 실제 순위는 나빠질 수 있다.

## 5. 먼저 탐색하고, 이후 좋은 후보를 따라 한다

| 시점 | 학습 방식 | 직관 |
|---|---|---|
| `t=0` | LLM 초기 rewrite에 NLL | 출발점 마련 |
| `t=1` | 10개 후보에 MBR | 여러 선택지를 보상과 함께 탐색 |
| `t≥2` | 보상 최고 후보에 NLL | 좋은 선택지를 집중해서 학습 |

위 일정은 논문의 `τ=1` 설정이다. MBR에서는 후보들에 대한 **모델 확률을 재정규화**하고, 그 확률로 보상을 가중 평균한다. 음의 기대 보상을 줄이면 높은 보상 후보에 더 많은 확률을 주는 방향으로 학습할 수 있다. 보상 자체에 softmax를 취해 label 확률로 쓰는 설명은 원문 Eq. (2)와 다르다. 이후에는 **생성 확률이 아닌 보상이 가장 높은 후보**를 골라 NLL로 학습한다. [원문 Algorithm 1, §3.2.2–3.2.3, Eq. (2)–(4)](https://aclanthology.org/2024.naacl-long.449.pdf#page=4)

여기서 반복은 **학습을 개선하는 반복**이다. 각 학습 반복에서 이전 모델이 만든 후보를 준비한다. 사용자의 새 질문마다 LLM 초기화와 gold passage 채점을 전부 반복하는 뜻이 아니다. 추론 때는 최종 재작성기의 질의를 기존 검색기에 넘긴다. [원문 §1, Fig. 2](https://aclanthology.org/2024.naacl-long.449.pdf#page=2)

## 6. 성능 향상을 어디까지 믿을 수 있나?

주요 평가 대상은 TopiOCQA와 QReCC의 문단 검색이다. 예를 들어 QReCC/BM25에서 ConvGQR 대비 IterCQR의 MRR은 `0.441 → 0.467`이지만, Recall@100은 `88.0 → 85.5`다. 이 둘은 모순이 아니다. 첫 관련 문단을 더 앞에 두는 성질과 넓은 후보 집합에서 관련 문단을 회수하는 성질은 다르다. 모든 지표가 개선됐다고 요약하면 안 된다. [원문 §4.1, Table 1](https://aclanthology.org/2024.naacl-long.449.pdf#page=6)

특히 **학습 보상은 dense 유사도, 최종 평가는 실제 검색 결과**다. BM25는 같은 점수 함수를 쓰지도 않는다. 저자도 dense 보상이 sparse 검색 성능을 일관되게 높인다고 보장할 수 없다는 한계, 초기 LLM 비용·의존성, 후보 저장·반복 학습 비용을 적었다. [원문 Limitations](https://aclanthology.org/2024.naacl-long.449.pdf#page=9)

## 7. 읽고 나서 직접 설명할 것

답을 외우기 전에 가상 예시를 새로 만들어 입력→rewrite→문단 순위를 말해 보자. 이어서 “왜 gold passage가 필요할까?”, “왜 cosine 상승이 MRR 상승을 보장하지 않을까?”, “어느 파라미터에 gradient가 흐를까?”를 종이에 설명한다. 막히면 [상세 설명](detailed-explanation.md)과 원문 §3으로 돌아가고, [퀴즈](quiz.md) 정답은 자신의 답을 적은 뒤 펼친다. 직접 이해했는지와 구현·재현했는지는 별도로 기록한다.
